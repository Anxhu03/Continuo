# Continuo Privacy & Data Governance Policy

**Last Updated:** September 2026  
**Status:** Production Standard  

At Continuo, we believe that context preservation should empower engineers without compromising user privacy. Because Continuo directly interacts with conversational AI interactions, **privacy is not an afterthought — it is an essential engineering feature.**

This document provides transparent, verifiable details on how user data is captured, processed, stored, and protected across the Continuo platform and Chrome Extension.

---

## 1. What Data is Captured?

Continuo captures:
1. **Dialogue Turns**: When you explicitly click **"Save Context"**, the extension extracts the conversation dialogue (user inputs and assistant outputs) from your active tab on supported platforms (ChatGPT, Claude, or Google Gemini).
2. **Tab Title**: Used as a default session label (e.g. "Refactoring Auth Engine - ChatGPT").
3. **Account Information**: Your email address and cryptographically hashed password for workspace authentication.
4. **Structured Project Memory**: The distilled architectural state generated by the Context Engine (goals, requirements, constraints, decisions, completed work, pending tasks, errors, code references).

Continuo **does NOT** capture:
- Browsing history or tabs outside the supported AI URLs.
- Keystrokes, passwords, or personal credentials entered in the browser.
- Session cookies, session tokens, or API keys belonging to ChatGPT, Claude, or Gemini.
- Background conversational text while the extension popup is closed.

---

## 2. Why is Data Captured?

Data is captured for one explicit reason: **to extract working state so that you can continue projects seamlessly across different AI models.** 

Instead of transferring raw, noisy chat transcripts, Continuo distills the dialogue into concise, structured Project Memory and formats an optimized prompt for your next AI destination.

---

## 3. Where is Data Stored?

1. **Local Browser Storage**:
   - The Chrome extension stores your active project ID and client preferences using `chrome.storage.local`.
   - Temporary captured text is stored in client memory only until persisted to the backend API.
2. **Backend Database**:
   - By default, local environments store data in an isolated SQLite database (`continuo.db`).
   - Production deployments connect to a secure, private PostgreSQL database instance managed by your organization or cloud provider.
   - All network transit between the extension, frontend, and backend occurs strictly over TLS (HTTPS/WSS).

---

## 4. How Long is Data Stored?

- Data remains stored in your personal Project Memory as long as you maintain the project.
- Continuo does not enforce artificial retention decay, ensuring your historical decisions and version diffs remain available when you resume long-term projects.
- You have permanent, unilateral control to delete records at any time (see Section 7).

---

## 5. Is Data Sent to Third-Party AI Providers or Used for Training?

- **Zero Foundation Model Training**: Your conversations and project memory are **never** used to train AI models, sold to data brokers, or shared with third parties.
- **Direct User-Initiated Continuation**: When you click "Continue with Claude", "Continue with ChatGPT", or "Continue with Gemini", Continuo formats a concise context payload into your system clipboard. You maintain complete human review before submitting that payload to the destination model.

---

## 6. How is Authentication Handled?

- **Secure Password Hashing**: Passwords are never stored in plaintext. They are salted with 16 random bytes and hashed using `PBKDF2-HMAC-SHA256` with 100,000 iterations.
- **Stateless JWT Authorization**: API sessions use JSON Web Tokens (JWT) signed with a server-side secret key (`HS256`).
- **Multi-Tenant Isolation**: Every database query enforces strict server-side project ownership (`WHERE project.user_id == current_user.id`). Users can never read, modify, or delete another user's projects, context packages, or handoffs.

---

## 7. How Users Can Delete Their Project Memory (Right to Erasure)

You have full control over your data:
- **Delete Project**: Deleting a project via the API (`DELETE /api/v1/projects/{project_id}`) or through the Workspace UI permanently deletes the project record, its version history, all associated context packages, raw transcripts, and handoffs in a single cascading deletion.
- **Manual Curation**: You can edit or remove specific requirements, decisions, or sensitive file paths from any Context Package at any time using the Project Memory Editor.
